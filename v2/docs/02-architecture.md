# 02 — المعمارية المخططة للتطبيق

> الحالة: **مخطط**. كود Flutter لسه مبدأش، والمرحلة الحالية هي بناء مكتبة النماذج والمحتوى.

## التقنية
| الطبقة | الاختيار | ملاحظة |
|---|---|---|
| الواجهة | Flutter (Dart) | كود واحد لـ Windows وAndroid، ومع إمكانية نسخة Web |
| عرض 3D | **Thermion** (مبني على Filament) كمرشح أول | **لازم تجربة الأول:** تحميل `contactor.glb`، والضغط على قطعة لاختيارها (picking)، والأداء على Windows وموبايل متوسط. ولو فشلت التجربة، البديل WebView + three.js |
| المحاكاة | Package مستقلة بـ Dart خالص (`cc_engine`) | نقل لمحرك JS الموجود في `index.html`، مع اختبارات لكل دايرة |
| المحتوى | JSON لكل مكون في `content/` + ملفات صوت | تعديل الشرح من غير لمس الكود |
| التفعيل والعضوية | سيرفر (Supabase أو Firebase أو Cloudflare Worker) | بدل النظام الحالي اللي بيتكسر (شوف تحت) |
| البناء والنشر | GitHub Actions: ملف APK ومثبّت Windows | |

## تقسيم الكود المقترح
```
app/
├── packages/cc_engine/        ← محاكاة الدواير (Dart خالص) + اختبارات
├── lib/
│   ├── core/                  ← نظام التصميم، والثيم، والترجمة، والتخزين
│   ├── features/library/      ← مكتبة المكونات: عارض 3D، وتفكيك، وكروت، وصوت
│   ├── features/ladder/       ← محرر ومحاكي المخطط الخطي
│   ├── features/panel_lab/    ← المعمل الحقيقي: صندوق، وريل، وتوصيل، وقياس
│   ├── features/exam/         ← الامتحانات والأعطال
│   └── features/admin/        ← لوحة الأدمن والتفعيل
└── assets/  ← GLB + content JSON + audio
```

## محرك المحاكاة (موجود ومجرّب في التطبيق الحالي)
المحرك الحالي في `index.html` (دوال `buildNets` و`solve` و`tick`) **صحيح وقوي**، وهيتنقل لـ Dart زي ما هو:
- بيبني الشبكات الكهربية (nets) من التوصيلات، ويحسب الجهد على كل ترمينال.
- بيكتشف القصر، ويفصل أصغر قاطع مسؤول عنه.
- الكويل بيشد بس لو الجهد في نطاقه، ولو الجهد ناقص بيزن.
- فيه انترلوك ميكانيكي، ومحول تحكم، وتايمرات On/Off-delay، وأوفرلود بزرار Test وReset.

## مشاكل في التطبيق الحالي لازم تتحل في v2
1. **العضوية المميزة بتتكسر:** `member_salt` منشور في `config.json`، ودالة توليد الكود (`devCode`) موجودة في كود المتصفح. فأي حد يقدر يولّد كود لجهازه. **الحل:** التحقق يبقى من سيرفر.
2. **باسورد الأدمن:** الـ hash بتاعه منشور من غير salt، فممكن يتخمّن offline لو الباسورد ضعيف. **الحل:** باسورد قوي، وتوكن GitHub نوعه fine-grained على المشروع ده بس.
3. **ملف واحد 384KB:** صعب تطويره. **الحل:** التقسيم اللي فوق.
4. **three.js r128 والخطوط من CDN:** محتاجين نت في أول فتح. **الحل:** كل حاجة تبقى جوه التطبيق.

## ربط النماذج بالتطبيق (العقد بين `models/` والتطبيق)
- كل GLB فيه **قطعة لكل جزء**، واسم القطعة هو `id` الجزء في ملف المحتوى.
- كل قطعة فيها extras: `name_ar` و`name_en` و`explode_mm` (اتجاه ومسافة التفكيك بالمللي).
- كل مسمار ترمينال فيه **Empty اسمه `TERM_<رقم>`**، زي `TERM_A1` و`TERM_13NO` و`TERM_2_T1`. وده مكان توصيل السلك في المعمل، ومربوط بالقطعة اللي شايلاه.
